# Demo — DB (`project-demo/DB/`)

## Stack detectado

- **MongoDB** con **Mongoose 9.1**
- **`csv-parse` 6.1**
- Node streams + `fs` + `dotenv`

## Estructura

```
DB/
├── add-routine-plan.js       CSV → RoutinePlan (Mongoose)
├── add-user.js
├── add-items-data-to-db.js
└── rutina.csv                 12 semanas × múltiples ejercicios
```

## Schema del plan (Mongoose)

`RoutinePlanSchema` con `routineExerciseSchema` anidado:

```js
routineExercise {
  week, day, session,
  exercise,
  prescription,       // ej. "3x10"
  rpe_target,
  cues,
  isCompleted,        // boolean
  log_*               // campos de tracking
}
```

## Features implementadas

- Carga en bulk del plan desde `rutina.csv` al cluster Mongo.
- Stream de parseo CSV con tolerancia a columnas "sucias" (comas sin escapar dentro de `Cues`).
- Schema flexible con RPE, cues y logs de ejecución.

## Lo que sirve (reutilizable) — **valor alto**

- **`rutina.csv`**: es un plan real completo de 12 semanas. **Activo crítico**: sirve como seed para validar el schema nuevo, como data de ejemplo para el entrenador-piloto, y como plantilla del futuro Google Sheet.
- **Modelo de ejercicio con `prescription + rpe + cues + logs`**: está más elaborado que lo que escribí en `specs/db/01-rutinas.md`. Conviene **enriquecer la nueva spec** con estos campos:
  - `rpe_target` → agregar a `plan_items`
  - `cues` → alinear con `notes` de `plan_items`
  - `prescription` → ya cubierto por `sets + reps + rest_seconds`
- **Estrategia de ingesta CSV**: el parser tolerante a comas dentro de campos es útil. Portarlo como seed script en `libs/db/seeds/` usando `csv-parse` + Prisma.
